# 003 Настройка чтения с реплик и консистентность

## Коллекция и операции

| Коллекция | Операция                                                | Primary/Secondary | Задержка репликации | Обоснование                                                                                                                                                                            |
| --------- | ------------------------------------------------------- | ----------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| products  | Получение категории товаров                             | Secondary         | 1-2 секунды         | Высокая частота чтения, обновление происходит не так часто, устаревшие данные не так критичны - могут быть отброщены в момент добавления товара в корзину.                             |
| products  | Получение информации о товаре                           | Secondary         | 1-2 секунды         | Высокая частота чтения, обновление происходит не так часто, устаревшие данные не так критичны - могут быть отброщены в момент добавления товара в корзину.                             |
| products  | Проверка остатков на складе                             | Primary           | 0 секунд            | Требуется строгая консистентность, любое устаревшее значение может привести к продаже недоступного товара                                                                              |
| carts     | Просмотр содержимого корзины                            | Primary           | 0 секунд            | Пользователь ожидает немедленного отображения о товарах в корзине, задержка может приводить к дублированию товара в корзине. Поэтому в качестве источника данных выбран primary.       |
| carts     | Количество товаров в корзине отображается в шапке сайта | Secondary         | 1-2 секунды         | В данном случае можно допустить получение данных из реплики тем самым снизить нагрузку на primary, пользователь готов к неконсистентность в отображении числа товоров в шапке страницы |
| orders    | Получение истории заказов пользователя                  | Secondary         | 1-2 секунды         | Высокая частота чтения, обновление происходит не так часто, устаревшие данные не так критичны - пользователь может допустить что новый заказа появиться в истории не сразу.            |
| orders    | Проверка статуса заказа                                 | Primary           | 0 секунд            | Требуется строгая консистентность, пользователь ожидает немедленного отображения статуса заказа, задержка может приводить к недопониманию и неудовлетворенности.                       |

## Рекомендации по настройке чтения из MongoDB:

- Для чтения из реплик рекомендуется использовать `readPreference` с настройкой `secondaryPreferred`, что позволит автоматически переключаться на реплику при недоступности primary, обеспечивая при этом высокую доступность данных.
- Для операций, требующих строгой консистентности, таких как проверка остатков на складе и отображение содержимого корзины, следует использовать `readPreference` с настройкой `primary`, чтобы гарантировать получение актуальных данных.

## Краткое резюме

- Primary используется для операций, требующих строгой консистентности, таких как проверка остатков на складе и отображение содержимого корзины.
- Secondary используется для операций, где допустима некоторая задержка в данных, таких как получение информации о товаре, просмотр истории заказов и отображение количества товаров в корзине. Это позволяет снизить нагрузку на primary и обеспечить высокую доступность данных.
